# 图书数据集导入操作指南

适用项目 书途智启 Library AI Agent  
适用人员 图书馆管理员与系统维护人员  
核对日期 2026 年 10 月 27 日

本指南说明如何把馆藏 Excel 导入当前项目，并让新图书进入检索与推荐。日常操作推荐使用管理后台：准备完整 XLSX 文件，上传并校验，检查异常，点击发布，最后验证推荐结果。维护人员也可使用第六部分的命令行方法。

## 一 开始前的准备

### 1 启动项目

打开项目根目录，启动 Docker Desktop，然后双击 `start.cmd`。等待窗口显示 `Ready`，再进入浏览器。首次构建可能需要较长时间，启动窗口未完成前先不要上传。

本地 Docker 部署通常打开 `http://localhost:4173`；家庭部署通常打开 `http://localhost:8180`。如果已有对外访问地址，使用实际地址。有 `.env.home` 时，默认启动会优先选择家庭部署；应确认登录的是准备导入数据的那套系统。

### 2 使用管理员账号登录

全新本地空数据库的默认账号为 `admin`，初始密码为 `BookPath@123`。如果部署时自定义过账号或修改过密码，使用实际账号。家庭部署的初始密码查看本机 `.env.home` 中的 `BOOTSTRAP_ADMIN_PASSWORD`；该值只代表首次初始化密码。

登录后进入管理后台，选择左侧的“馆藏数据管理”。管理员登录后通常会自动进入 `/admin`。首次使用默认密码登录后，应在“用户管理”中修改密码。学生账号没有导入权限。

### 3 准备需要上传的文件

项目已提供馆藏示例文件，可直接选择：

`resources/knowledge_base/books/ShiepbookInfo.xlsx`

自己的数据也应整理为 `.xlsx`。CSV 和旧版 `.xls` 请先在 Excel 中另存为真正的“Excel 工作簿（*.xlsx）”，不能只修改文件扩展名。后台默认限制为 64 MiB，即 67,108,864 字节；部署方可能调整此限制。

开始前保留原始文件和当前完整馆藏的备份。第一次熟悉流程时，可在独立测试环境导入少量样例；正式环境请使用完整馆藏文件。

## 二 整理 Excel 表格

### 1 把表头放在第一个工作表的第一行

导入器只读取工作簿中的第一个工作表。把实际数据表移到最前面；第一行直接填写字段名，第二行开始填写数据。删除表头上方的说明和大标题，避免合并表头，关键字段使用直接值而非公式。

以下八个列名必须存在，顺序可以调整。“必须有列”与“每格必须有值”是两回事；建议按下表补齐内容。

| 列名 | 填写方法 | 示例 |
|---|---|---|
| 序号 | 建议填写连续正整数，不要使用字母编号 | 1 |
| 题名 | 每行必须有书名，留空会跳过该行 | Python 编程入门 |
| 索书号 | 按馆内实际索书号填写，建议设为文本 | TP311.56/A1 |
| 馆藏地 | 图书所属馆藏地点 | 临港书库 |
| 所在地 | 图书当前所在地点 | 临港书库 |
| 书刊状态 | 按实际状态填写中文文字 | 在架 |
| 流通状态 | 按实际流通规则填写中文文字 | 可借 |
| ISBN | 建议设为文本；允许缺失，会统计缺失数量 | 978-7-302-00000-0 |

表中的 ISBN 仅示意书写格式，正式数据请填写图书实际 ISBN。系统校验 ISBN 校验位，不能用随意编造的编号替代。

### 2 尽量补充书目信息

支持的可选列包括：`责任者`、`责任者附注`、`出版社`、`出版年`、`简介`、`页码`、`价格`、`卷期`、`排架号`、`入藏时间`、`更新时间`。有真实简介时尽量保留，便于检索与推荐。日期建议使用 `2026-10-27` 或 `2026/10/27`。

### 3 按馆藏副本组织每一行

一行代表一个馆藏副本。同一本书有三册时，可保留三行，分别填写各册地点与状态。系统按有效 ISBN 聚合书目；没有有效 ISBN 时，按题名、责任者、出版社、出版年和卷期组合聚合。不要只因书名相同就删除真实副本，也不要额外复制重复行。

## 三 在后台上传并发布

### 第一步 选择文件并上传

进入“馆藏数据管理”，在“上传新版馆藏”区域点击文件选择框，选择整理好的完整 `.xlsx`，再点击“上传并校验”。看到“上传成功，后台正在清洗。”后，查看下方“导入批次”。

如果提示“该文件已存在，已定位到原批次。”，表示文件内容与已有批次相同。此时查看原批次状态；仅更改文件名不会触发重新导入。

### 第二步 等待后台清洗完成

页面每 3 秒刷新运行状态，也可以手动点击“刷新”。处理阶段可能显示 `uploaded`、`cleaning`、`deduplicating`。较大的馆藏文件可能处理数分钟，应保持服务运行，避免在处理中停止或重新构建后端。

出现以下组合，表示清洗完成，可以进入发布前检查：

状态 `succeeded`，处理阶段 `ready_to_publish`，操作栏出现“发布”。

此时即使进度显示 100%，也仅表示清洗步骤完成，图书仍处于草稿版本。

### 第三步 查看统计和异常报告

核对“统计 / 错误”列，再点击“异常报告”。报告展示前 100 条问题样例，可看到 Excel 行号、字段、问题说明和原始值。没有显示问题记录时，不会出现报告明细面板。

“题名为空”的行会被跳过。ISBN 无效会计入异常，但该行有题名时仍可保留，并使用书目信息参与聚合。确认跳过数量和异常是否可接受；如需修正，修改原 Excel，保存后重新上传，选择修正后的批次发布。

### 第四步 点击发布

在目标批次的操作栏点击“发布”。页面会提示“正在生成标签和索引，成功后自动发布。”。系统依次生成规则标签、构建向量索引，然后发布新馆藏。无需再到“AI 标签审核”点击生成按钮，才能完成基础导入。

### 第五步 等待发布完成

发布中通常显示 `tagging` 或 `indexing`，进度可能从清洗完成的 100% 转为 70% 或 85%，这是进入发布步骤后的阶段进度。最终应同时看到：状态 `succeeded`、处理阶段 `published`、进度 100%。记录文件名和导入时间，再进行下一页的结果验证。

## 四 检查导入结果与后续更新

### 1 看懂数量变化

| 统计字段 | 含义 | 检查重点 |
|---|---|---|
| raw_rows | 读取的数据行数，不含表头 | 与源表数据量是否相符 |
| valid_rows | 保留的数据行数 | 加上 skipped_rows 应等于 raw_rows |
| skipped_rows | 被跳过的行数 | 当前主要检查题名为空的行 |
| books | 聚合后的书目数 | 通常小于或等于馆藏副本数 |
| holdings | 导入的馆藏副本数 | 正常情况下等于 valid_rows |
| isbn_valid / missing / invalid | 有效、缺失、无效 ISBN 行数 | 统计对象是保留行，不是去重书目 |
| issues | 记录的数据问题数 | 与异常报告结合检查 |

后台列表可能只显示这些统计的一部分。维护人员可通过导入批次接口查看完整 `statistics`。例：一张表含 100 行，其中 2 行没有题名，其余 98 行聚合成 60 本书，则预期为 raw_rows 100、valid_rows 98、skipped_rows 2、books 60、holdings 98。

### 2 到实际使用页面验证

使用普通学生账号进入工作台，针对数据中确实存在的主题发起推荐，例如“推荐几本 Python 入门书”。检查能否返回图书，并抽查书名、索书号、馆藏地点和可借状态。若需要注册，按部署方实际注册或邀请码规则完成。

推荐结果受目标、用户资料和图书状态影响，不保证某本书一定排名第一。若返回空结果，先选取源表中确实存在的主题，再检查该批次是否已到 `published`。对话生成还受模型 API 配置影响；模型接口报错时，应与馆藏导入问题分别处理。

### 3 后续更新仍然上传完整馆藏

后台每次发布会启用一套新的数据版本，并归档旧的已发布版本。因此，新文件应包含更新后仍需提供服务的全部馆藏；只上传新增的 100 本书，会让新版本仅包含这部分书目，不能实现追加导入。

完整更新流程：导出最新全量馆藏 → 整理字段 → 上传新文件 → 检查统计和异常 → 发布 → 再次验证。不要将多个分片依次发布当作一个完整数据集。

### 4 完成检查

确认已发布、数量合理、关键异常已核对、学生端推荐可用，并保存源文件和操作日期。AI 批量标签及人工审核属于后续内容增强，不是基础导入的必做步骤。

## 五 常见问题处理

### 无法选择文件或提示格式错误

确认文件是真正的 `.xlsx`，不是 CSV 或 `.xls` 改名。用 Excel 重新打开并另存为 XLSX 后再传。提示文件为空或超过大小限制时，确认文件有内容且符合部署限制。超过 64 MiB 的完整数据集应交给维护人员处理上传限制或使用命令行，不能通过逐片发布拼接。

### 提示 missing required columns

检查第一个工作表的第一行是否包含八个准确列名。特别注意“书刊状态”不能写成“图书状态”，“题名”不能写成“书名”。表头上方不要放合并标题，也不要把正确表格留在第二个工作表。

### 提示数值转换错误或序号异常

序号建议使用 1、2、3 等正整数，删除 `A001`、“第 1 册”等非数字内容。检查 Excel 是否带入空白尾行、公式错误或多余说明行，整理后保存新文件。

### 有异常但批次显示成功

清洗成功不代表源表每行都没有问题。核对 skipped_rows、isbn_invalid 和异常报告。题名为空会跳过；ISBN 无效通常不会阻止该行入库。优先修复影响书目识别和馆藏使用的信息，然后重新上传修正版。

### 没有发布按钮或推荐仍然为空

只有 `succeeded` 且阶段为 `ready_to_publish` 的批次显示“发布”。阶段仍在运行时继续等待；失败时查看“统计 / 错误”。已经 `published` 的批次不再显示发布按钮。若只上传而未发布，学生端不会使用该草稿。

### 发布失败或任务长时间不变化

记录批次、阶段、时间和错误摘要，交给维护人员检查后端与数据库、索引存储及资源占用。后台对相同内容文件直接返回原批次，不会自动重新启动失败任务；不要只改名反复上传。数据错误可修正后另存并上传；环境故障应先修复，再由维护人员安排重试。

### 维护人员查看错误

本地 Docker 部署可在项目根目录执行以下命令，查看最近的后端日志：

```powershell
docker compose logs --tail 100 backend
```

家庭部署使用第六部分说明的完整 Compose 前缀。后台新版本只有标签和索引全部成功后才切换；发布失败时，已有线上版本仍可使用。首次导入失败则尚无可用的线上馆藏。

## 六 维护人员命令行导入

本节适用于本地 Docker 部署的首次初始化或维护窗口。日常更新优先使用后台流程。命令行默认导入会直接发布书目版本，随后还要生成规则标签和索引，三条操作之间存在推荐能力尚未完整就绪的时间。

### 1 打开项目根目录的 PowerShell

确认项目已经启动。以下命令以项目自带 XLSX 为例，逐条执行，每条成功结束后再继续。导入自己的文件时，只替换第一条命令中的源文件路径。

### 2 复制 Excel 到后端容器

```powershell
docker compose cp "resources/knowledge_base/books/ShiepbookInfo.xlsx" backend:/tmp/library.xlsx
```

### 3 导入馆藏

```powershell
docker compose exec backend .venv/bin/python -m app.cli import-library /tmp/library.xlsx
```

成功后输出包含 `data_version_id`、书目数、馆藏副本数等信息的 JSON。保存版本 ID；相同文件再次导入可能返回 `duplicate_file: true`。

### 4 生成规则标签

```powershell
docker compose exec backend .venv/bin/python -m app.cli tag-books
```

### 5 构建检索索引

```powershell
docker compose exec backend .venv/bin/python -m app.cli build-index
```

后两条命令默认操作最近发布的版本。若存在多版本并行维护，在两条命令末尾加 `--version 实际版本UUID`，填入第三步输出的 ID。确认两步均输出 `processed` 数量，再按第四部分验证学生端推荐。命令行默认导入的 `published` 状态本身不代表这两步已经完成。

### 6 家庭部署如何替换命令前缀

以上各条命令中的 `docker compose` 均替换为：

```powershell
docker compose --env-file .env.home -f docker-compose.home.yml
```

其余参数保持一致。必须使用启动该系统时对应的配置，避免把数据导入另一套数据库。本文依据当前仓库的导入器、后台页面和部署说明编写；文档制作期间未实际上传、发布或更改现有馆藏。
