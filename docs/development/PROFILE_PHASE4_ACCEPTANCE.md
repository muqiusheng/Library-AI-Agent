# 第四阶段：统一展示与整体验收

## 已交付

- 画像页优先展示接口返回的 effective_profile，原始基础画像保留用于字段编辑。
- 目标或兴趣为空时显示暂未设置，不回退到旧值。
- 以知识点、明确水平、来源及时间替代原先按记忆数量计算的雷达图。
- 未学习与尚不确定分别展示，学习成就和历史记录不参与能力评分。
- 生效字段可展开原文依据；后端按会话归属读取依据，防止引用其他用户的消息。
- 注册填写字段也包含来源与档案更新时间，不凭空补充来源消息。
- 当前生效、未采用、历史版本和学习记录分别标明；历史开关与分页独立于有效画像。
- 基础画像表单只提交改变的字段，能力记录使用结构化水平编辑，目标/兴趣保留数组类型。
- 修改、删除后重新读取有效画像，保留历史开关；支持错误提示、重试、空状态。
- 手工清空学习目标被视为有效更新；注册时的必填规则未改变。

## 真实环境待验收流程

1. 以测试账号说明“我没学过 Python，推荐相关图书”，确认本轮推荐快照采用新事实。
2. 打开画像页，确认 Python 显示未学习、来源为对话，并能展开原文。
3. 手工改成有基础，再在对话中陈述相反事实，确认出现询问且未直接覆盖。
4. 分别测试确认和保留原画像，核对页面、有效画像及推荐快照一致。
5. 删除动态事实，查看历史版本，确认历史本身不会恢复为有效事实。
6. 检查清空兴趣/目标、仅改专业、切换账号、新会话、模型不可用等情况。
7. 在真实 PostgreSQL 中检查版本持久化及并发更新保护。

注意：删除动态事实不等同于删除用户另外填写的基础信息，回退来源会明确展示。
图书数据集、馆藏导入和数据库表结构在本阶段均未修改。
