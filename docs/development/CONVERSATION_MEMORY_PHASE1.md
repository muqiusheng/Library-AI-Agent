# 多轮记忆第一阶段

本阶段改造同一会话内的连续推荐。保留馆藏数据、基础画像和既有页面布局，
没有数据库迁移，也没有重新导入数据或重建索引。

## 处理流程

1. 保存用户消息，按用户归属查询近期消息。
2. 统一组装基础画像、任务状态、筛选条件、最近推荐列表。
3. 结构化解析为推荐、调整、解释、可借查询、普通聊天或澄清。
4. 更新任务状态，补全省略主题的需求，再执行检索、评分、重排和推荐说明。
5. 指定某本书时，按真实推荐顺序、完整书名或已确认焦点定位图书。
6. 可借查询从当前馆藏读取；单本替换保留其余图书，整批替换排除上一批。

任务状态存放于 `conversation_constraints.constraints_json._task`。
原有三个筛选字段仍在 JSON 顶层，约束接口保持原响应结构。
没有任务状态的旧会话从最近推荐查询恢复初始主题。

消息请求的 `only_available` 可省略或为 null，表示不改变当前条件；
显式 true/false 表示设置/取消。自然语言取消与设置在服务端解析。
流式响应新增 `constraints_updated` 事件，使前端开关同步实际状态。
手工修改约束时保留 `_task`，`difficulty: null` 可以清除难度覆盖。

## 手工验收

在有已发布馆藏的环境中，顺序输入：

1. 推荐 Java 入门图书，只看可借。
2. 再简单一点。
3. 不要第一本，换一本。
4. 第二本现在能借吗？
5. 为什么推荐第二本？
6. 它现在能借吗？
7. 不必只看可借。
8. 换一批。
9. 另外推荐 Python 图书。

应确认主题继承、单本替换其余结果不变、查询和解释不生成新推荐集、
指代对应正确图书、可借开关同步，以及切换主题清除临时条件。
对于无法确定的“这本”“换一本”或越界序号，应要求澄清。

## 自动检查

```powershell
uv run pytest tests/test_conversation_memory.py tests/test_general_chat.py -q
cd frontend
npm run type-check
npm test
```

新测试使用隔离的内存数据库、临时书目和模拟模型响应，覆盖流式入口及实际推荐服务。
测试不访问本地图书数据集，不调用收费模型接口。内存数据库测试不能替代 PostgreSQL
部署集成验证，模拟模型结果也不能作为实际模型识别率的测量。

跨会话动态画像合并、长期记忆冲突处理和长对话摘要属于后续阶段。
