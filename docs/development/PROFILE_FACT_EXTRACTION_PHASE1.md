# 画像优化第一阶段：可靠提取事实

## 范围

本阶段只优化事实提取和进入现有记忆写入链路前的校验。
不合并基础画像与动态事实，不改变推荐评分或画像页面，也不迁移旧记忆键。
图书数据集和数据库表结构均不变。

## 当前流程

1. 提取入口只处理用户消息，按会话归属读取当前消息之前的最近八条消息。
2. 模型返回类别、知识点、JSON 值、主体、作用范围、当前消息原文证据和置信度。
3. 校验类别、值类型、能力等级和证据；只保留明确的本人长期事实。
4. 标准化 Python、Java、JavaScript、C++、机器学习等知识点；未知知识点保留独立名称。
5. 同一次结果中的同键事实去重，目标和兴趣合并，当前消息中较后的能力陈述优先。
6. 通过原有服务写入动态记忆，来源仍指向当前用户消息，保留原有手工编辑保护。

能力等级为 `none/basic/intermediate/advanced/unknown`，并标记 `basis=self_report`。
这是自报基础，不代表能力测评结果；未知不等于零基础。
历史只用于理解当前表达，不能重新提取历史信息或把助手的推断写为用户事实。

## 规则与边界

- “我没学过 Python”：可以保存 Python 未学习事实。
- “你学过 Python 吗？”后回答“没有”：可以结合前文提取。
- 无前文、询问多个知识点、询问朋友基础后回答“没有”：不保存本人能力。
- “我想学 Python”：可以保存目标，不能推断为 Python 零基础。
- “帮朋友找书”“假设我零基础”“这次想看简单点”：不作为本人长期事实。
- “帮朋友找书，我没学过 Python”：逐项判断，保留明确的本人陈述。
- 模型不可用、结构化输出失败或证据不足：不写入新事实。

服务端使用主体、范围、原文定位、类别值检查及保守措辞规则进行过滤。
置信度最低接受值为 0.75，这是可调整的工程筛选阈值，不是经校准的准确率。
措辞规则以中文常见表达为主；隐含语义和新领域名称仍依赖模型识别，可能保守漏提取。

## 自动验证

```powershell
uv run pytest tests/test_profile_fact_extraction.py tests/test_conversation_memory.py tests/test_general_chat.py -q
```

覆盖结构校验、语义过滤、短回答、名称归一、证据约束、同消息内重复与修正、模型失败、
会话时间边界、用户归属、手工优先，以及流式入口实际写入。
使用模拟模型和隔离内存数据库，不访问图书数据集或收费模型。

已修正 `tests/test_profile_memory.py` 中同步调用异步提取方法的问题，
并让该测试使用确定的模拟提取结果；它仍需要 PostgreSQL 与现有 API 测试环境。

## 真实模型验收

在可用数据库和模型环境下，检查“本人事实、短回答、他人信息、临时要求、假设、混合表达”
各组真实对话的提取结果和来源消息。自动测试通过不代表实际模型的语义识别率已经测得。
后续阶段再处理跨消息冲突、旧键迁移、有效画像合并与推荐适配。
