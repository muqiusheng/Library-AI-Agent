# 画像优化第二、三阶段

## 范围

第二阶段规范更新并生成有效画像；第三阶段将有效画像接入对话、检索、评分、重排和推荐说明。
不修改图书数据集、画像页面或雷达图，不增加数据库迁移，也不实现长对话摘要。

## 有效画像

`EffectiveProfileService` 以基础画像为起点，读取本用户的记忆版本并按规范身份归组：

- Python、Python 编程等别名归到同一知识点，Java 与 JavaScript 保持区别。
- 旧能力值 beginner 读取时归为 basic；保留旧原始记录，后续写入使用规范身份。
- 同键有效手工事实优先，自动事实要求置信度至少 0.75；不把未知能力当零基础。
- 删除当前事实同时停用其别名版本，避免旧版本重新生效；删除失效历史不会删除新版本。
- 不含有效动态覆盖时回退基础字段；删除动态记录不代表删除用户另外填写的基础字段。
- 输出 abilities、sources，包含来源、记忆 ID、来源消息、时间、置信度和手工标记。
- 学习成就仍是成就，不据此直接推断掌握某项能力。

`GET/PATCH /api/v1/profile` 保留原 profile、memories，并增加 effective_profile 字段。
本阶段前端仍展示原接口字段，页面统一展示留到第四阶段。

## 更新规则

自动事实按规范身份去重和替换，保留失效历史。同值不新增版本。
手工确认可以将自动事实升级为手工事实；手工整体修改现有基础时重置旧能力事实，
对明确提及的常见知识点和水平生成新的手工能力记录，不从泛泛描述推断所有领域。

目标与兴趣支持 add/set/remove；同条消息中的操作按原文顺序执行。
例如“不再对 Python 感兴趣，我喜欢 Java”会移除 Python、补充 Java。

自动事实与手工事实冲突时不覆盖，在会话内询问“是否更新画像”。
用户明确确认后再次检查受保护版本是否仍有效，避免覆盖在此期间的其他手工编辑。
拒绝则保持原画像。若原消息同时包含荐书请求，确认成功后继续处理该请求。
单个用户的更新在 PostgreSQL 使用用户行锁串行化；版本时间保持单调递增。

## 对话与推荐

事实提取位于本轮需求解析之前，统一上下文随即刷新有效画像，因此本轮即可生效。
新会话也读取同一份有效画像。

难度匹配优先级：

1. 当前会话明确指定的难度。
2. 历史太难/太简单反馈形成的偏向。
3. 有效的长期难度偏好。
4. 与当前主题或明确前置知识相关的已知能力。
5. 基础画像默认偏好。

只使用相关知识点，例如 Python 未学习不会降低 Java 推荐难度。
当前提供少量明确前置关系：LangChain→Python、深度学习→机器学习，不是完整课程知识图谱。

查询改写接收有效画像与本轮有效难度；无模型时对相关基础不足的请求补充基础检索词，
明确进阶要求不会被基础检索词覆盖。
真实排序使用有效专业、兴趣、学习目标和能力难度适配，画像并非只用于末尾提醒。
推荐集合保存生成时的画像与实际条件快照，说明沿用该快照，避免后续画像变化改变旧推荐依据。


覆盖去重、能力纠正、旧别名、手工确认、删除、用户隔离、跨会话读取、同轮生效、
真实推荐排序变化、当前条件优先、目标对分数的影响、模型各环节输入及推荐快照。
